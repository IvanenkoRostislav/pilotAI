# TablePilot AI

AI-агент бронює столик через Telegram від імені користувача: сам починає розмову,
генерує англійські відповіді через Gemini, уточнює невідомі дані та завершує
сценарій після доставки фінального підтвердження. Спілкування лише текстове.
Голосові та вкладення не розпізнаються: агент просить надіслати текст.

## Запуск

Потрібні Node.js 24+, npm, Telegram API ID/Hash та ключ Gemini.
Основна модель: `gemini-3.1-flash-lite`, резервна: `gemini-3.5-flash-lite`.
FFmpeg, мікрофон і сервіси озвучення не потрібні.

1. Виконай `npm ci`.
2. Скопіюй `.env.example` у `.env` та заповни ключі, `GEMINI_MODEL` і
   `TARGET_USERNAME` **тестового другого Telegram-акаунта**.
3. Параметри завдання: `BOOKING_GUESTS=2`, `BOOKING_TIME=17:00`. Дата визначається
   при `/book` за `Europe/London`. Якщо 17:00 уже минула, агент відмовиться
   запускати нове бронювання; він не переносить його на завтра.
4. `BOOKING_RESTAURANT` можна залишити порожнім: назву агент запитає в менеджера.
   За бажанням заповни справжні `BOOKING_NAME`, `BOOKING_PHONE`, `BOOKING_EMAIL`.
   Порожні персональні дані агент запитає в консолі лише за потреби.
5. Запусти `npm run dev`. За першого входу введи номер телефону, код і, якщо
   потрібно, пароль Telegram. Сесія зберігається в `.sessions/`.
6. Введи **`/book` у консолі**. Агент сам надішле перше повідомлення адресату.

Зміни коду чи `.env` потребують перезапуску: `npm run dev` не є watch-режимом.
Альтернатива для зібраного застосунку: `npm run build`, потім `npm start`.
Не запускай одночасно кілька процесів із тією самою Telegram-сесією.

Реальний адресат завдання — `@vlad_dev_7`. Не встановлюй його для локальної
перевірки. Контакт із ним дозволений лише після окремого дозволу власника.

## Керування бронюванням

| Команда в консолі | Дія |
| --- | --- |
| `/book` | Одна спроба бронювання в цьому процесі; перше повідомлення надсилає агент |
| `/status` | Стан, параметри та поле, яке очікується від власника |
| `/input name Справжнє ім’я` | Надати запитане ім’я гостя |
| `/input phone +44...` | Надати запитаний телефон |
| `/input email guest@example.com` | Надати запитану пошту |
| `/input restaurant Назва` | Надати назву, якщо її запитано у власника |
| `/input other Відповідь` | Відповісти на інше уточнення, наприклад щодо місця або умов |
| `/stop` | Зупинити локальну роботу агента; вже створену бронь не скасовує |
| `/quit` | Вийти з програми |

Після завершення, відмови чи зупинки для нового `/book` перезапусти процес.
Для тимчасових помилок Gemini (408/5xx або мережа) виконуються до трьох AI-запитів.
Якщо вони не допомогли, контекст зберігається: повтори `/book` без перезапуску.
Повторюються лише AI-запити, а не надсилання повідомлень Telegram.
`GEMINI_FALLBACK_MODEL` задає резервну модель для текстового діалогу.
Після тимчасового збою перший повтор AI-запиту переходить на резервну модель;
текст і контекст залишаються тими самими. Квоти конкретного API-проєкту тут не припускаються.
Під час очікування відповіді власника агент пам'ятає повідомлення менеджера
та може відповідати на них. Ім’я менеджера не стає ім’ям гостя. Зміна часу,
дати або кількості гостей потребує окремого нового бронювання; пропозицію
менеджера агент самостійно не приймає. Наявні допоміжні команди звичайного чату
збережено, але для перевірки завдання використовуй `/book`.

## Архітектура

- TypeScript / Node.js: конфігурація, стани та перевірки перед діями.
- Teleproto: Telegram-клієнт та приватні текстові повідомлення.
- `@google/genai`: AI-планування, генерація власних реплік, окрема перевірка
  фактів/умов у запропонованій відповіді.
- JSONL: лог повідомлень і коротких рішень, окремо від технічних подій.

Агент не обирає текст із заготовленого сценарію. Код перевіряє стани, походження
назви ресторану, наявність персональних даних, повноту фінального зведення та
явне підтвердження. Додатковий AI-запит перевіряє кожну запропоновану репліку;
для небезпечної відповіді дозволена одна спроба виправлення. Це додає затримку
та витрати Gemini. Захист із використанням AI не є формальною гарантією фактів.

## Логи для здачі

`logs/agent-YYYY-MM-DD.jsonl` — один запис `conversation.message` на повідомлення:
`timestamp`, `sender`, `direction`, `messageType`, `text`, `understood`, `decision`,
`state`, `bookingSessionId`. Тип `TEXT` означає текстове повідомлення, `MEDIA` —
непідтримуване вкладення. Вкладення не завантажуються і не надсилаються в AI.
Дата і часові мітки файлів — UTC.

Ключі, токени, контакти й відомі персональні значення маскуються. Довільний текст
розмови зберігається після маскування; невідомі заздалегідь персональні дані можуть
залишатися в ньому. Переглянь лог перед передачею третім особам. `.env`, `.sessions`,
`logs` та `output` виключені з Git.

У PowerShell можна отримати лише записи однієї розмови:

```powershell
Get-Content logs/agent-YYYY-MM-DD.jsonl |
  ConvertFrom-Json |
  Where-Object bookingSessionId -eq 'UUID-з-події-booking.started' |
  ConvertTo-Json -Depth 6
```

## Перевірки

```sh
npm run typecheck
npm test
npm run build
# Реальні API-запити, витрачають квоту, без Telegram:
npm run check:booking -- --live
```

Автоматичні тести підміняють Telegram і AI, перевіряють повний текстовий діалог,
невідомі дані, альтернативи, неоднозначне підтвердження, відмову, резервну модель,
дублікати, нові повідомлення під час генерації та зупинку. Голосові/вкладення
перевіряються як непідтримувані: без завантаження, озвучення або AI-виклику.
`check:booking --live` використовує синтетичні дані, фіксований тестовий годинник
та справжній Gemini; адресату Telegram нічого не надсилає. Це перевірка поведінки
моделі, а не доказ реального бронювання.
