# Фактичні результати перевірок

## Попередній етап розробки

Після вилучення голосового функціоналу команда `npm test` завершилася результатом:
63 тести пройдено, 0 помилок, 0 пропущених. Перед нею виконалася збірка `tsc`.
Окрема `npm run typecheck` також пройшла. Це результати попереднього етапу роботи,
а не новий запуск під час підготовки до здачі.

Тести використовували підміни Telegram та AI й охоплювали:

- повне текстове бронювання, запит імені через консоль та фінальне зведення;
- невідому й задану назву ресторану, ім'я менеджера та персональні дані гостя;
- альтернативний час, відмову, неоднозначні та суперечливі підтвердження;
- тимчасові збої API, резервну модель і повторний `/book` зі збереженням контексту;
- дублікати, нові повідомлення під час генерації, `/stop` і завершення діалогу;
- запит тексту замість вкладень без завантаження або надсилання аудіо;
- текст із попереднім переглядом посилання, формат логів і маскування секретів.

Раніше також проводилися синтетичні перевірки зі справжнім Gemini, зокрема
генерація першого повідомлення та завершення тестового сценарію. Вони належать
попереднім версіям і не доводять результату поточного реального бронювання.

## Підготовка до здачі 18 листопада 2026

На цьому етапі виконано лише читання коду, локальних журналів, конфігурації та
Git-історії, віддалене читання SHA гілки GitHub і редагування документації.
Тести, збірка, AI-запити й агент не запускалися; повідомлення менеджеру не надсилалися.
Наявна активна сесія не переривалася.

За знімком журналів о 14:48 UTC:

- серед них 42 записи `conversation.message`, з яких 23 відповідають поточній

- у поточних записах перевірено обов'язкові поля, напрямок/відправника, часові

- ідентичних дублів записів і подій `logger.write_failed` не знайдено;
- завершена текстова спроба містить 13 повідомлень: 8 вихідних і 5 вхідних,

- пізніша спроба має початкове вихідне повідомлення і стан `NEGOTIATING`, без

Ці числа описують збережені дані на час читання. Подальші записи активного
процесу можуть змінити кількість рядків. Повноту листування не звіряли з історією
Telegram або системою ресторану. Деталі: [аудит підготовки](submission-audit.md).

## Окреме виправлення після реальної розмови

Після описаного вище аудиту власник окремо дозволив невелику правку коду:
менеджер повідомив про звільнення потрібного столика вже після відмови, але
агент у стані `FAILED` проігнорував оновлення. Для відсутності місць додано
стан `WAITING_AVAILABILITY` замість технічного завершення. Нові повідомлення
обробляються в тій самій спробі; попередні факти, параметри та UUID зберігаються.

Додано регресійний сценарій із підмінами: відмова → запитання «людина чи бот?»
→ запитання про ім'я менеджера → новина про столик на початкові 17:00
→ запит підтвердження → явна згода → фінальне зведення. Окремий тест перевіряє
проходження такого оновлення через Telegram-транспорт із підміненим клієнтом.
Також перевірено відсутність повторних прощань, скасування очікування через
`/stop` та заборону бронювання після того, як потрібний час минув.

`npm test` після цієї правки: **68 тестів пройдено**, 0 помилок, 0 пропущених;
перед тестами успішно виконано збірку. `npm run typecheck` також пройшла.
Це локальні перевірки; справжній процес агента не перезапускався, сесія не
переривалася, API Gemini не викликався та повідомлення менеджеру не надсилалися.
Уже запущений старий процес не підхоплює ці зміни автоматично; відтворення
раніше пропущених повідомлень із Telegram або відновлення процесу з логів не додано.

## Погодження альтернатив, привітання, календар та AI-відповідь

За наступним окремим запитом додано кодові перевірки перед надсиланням, а не
лише інструкції для моделі:

- альтернативна година, зокрема «half five», «five thirty», 5:30 pm і 17:30,
  не може бути запропонована від імені гостя без погодження власника;
- неоднозначні прийняття на кшталт «later works» також відхиляються, якщо є
  непогоджена пропозиція; явний дозвіл — `/input time HH:mm`, відмова — `/input time no`;
- погодити можна лише запропонований менеджером майбутній час. Дата й кількість
  гостей не змінюються; початкові параметри зберігаються окремо;
- початкове привітання прибирається з наступних реплік;
- правильний день тижня обчислюється з дати; неправильний день у репліці
  змушує її перегенерувати. Перевірено середу для 18 листопада 2026 року й
  перехід лондонської дати на наступну добу влітку;
- на запитання про AI неправдива відповідь «я людина» не надсилається;
- запит депозиту/картки призупиняє погодження до відповіді власника. Карткові
  дані не приймаються через консоль і не надсилаються менеджеру; згода на
  іншу суму не погоджує запитаного депозиту. Функції виконання платежу немає.

Після цих змін `npm test` пройшла: **80 тестів**, 0 помилок і 0 пропущених.
Перед тестами пройшла збірка; також перевірено типи. Нові регресійні тести
навмисно схвалюють усі тексти в підміненому AI-рецензенті, щоб окремо перевірити
кодові обмеження. Погодження часу додатково проходить через підміну Telegram
і справжній розбір команди консолі. Це локальні тести, а не нова реальна переписка.
Поточний процес агента не перезапускався, його сесію не переривали, повідомлень
менеджеру та нових запитів Gemini під час цього виправлення не надсилали.
