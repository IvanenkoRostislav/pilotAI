# Голосові повідомлення

Голосовий транспорт працює в `/book` та `/chat on`. Telegram не запускається
під час тестів або діагностики моделей.

## Налаштування

Використовується наявний `GEMINI_API_KEY`. Додаткові необов'язкові змінні:

```dotenv
GEMINI_TRANSCRIPTION_MODEL=gemini-3.1-flash-lite
GEMINI_TTS_MODEL=gemini-3.1-flash-tts-preview
GEMINI_TTS_VOICE=Kore
FFMPEG_PATH=ffmpeg
```

FFmpeg має бути доступний у PATH або за абсолютним шляхом `FFMPEG_PATH`
та підтримувати кодек `libopus`. Нових npm-залежностей немає.

## Поведінка

- Перше вихідне повідомлення процесу та вступне повідомлення `/book` — текстові.
- Наступна відповідь на текст — текстова; на Telegram Voice — голосова.
- Транскрипції потрапляють у той самий BookingAgent/Gemini-контекст, що й текст.
  Окремої історії для аудіо немає. Для `/input` зберігається формат повідомлення,
  яке спричинило запит даних.
- Якщо агент очікує загальне уточнення (`other`), нове повідомлення менеджера
  автоматично повторно аналізується з повним контекстом. Так повне друге
  голосове може замінити запит `other` на `name` без ручного `/input other`.
  Запити імені, телефону, email і назви ресторану залишаються за власником;
  нова репліка менеджера не вважається згодою власника на депозит чи зміну умов.
- Приймаються OGG voice notes до 10 MiB та 180 секунд. Інші вкладення
  обробляються як раніше. Вхідне аудіо завантажується в пам'ять і передається
  Gemini як `audio/ogg`; файли на диску для нього не створюються.
- TTS отримує готовий текст агента з вимогою прочитати його дослівно з
  британською вимовою (`en-GB`). Голос `Kore` можна замінити через налаштування.
  Акцент задається інструкцією моделі; він не є гарантованою властивістю імені голосу.
- PCM (mono, signed 16-bit little-endian, частота з MIME відповіді Gemini)
  перетворюється FFmpeg у OGG/Opus, mono 48 kHz, 32 kbps, режим `voip`.
  Унікальна тимчасова папка видаляється в `finally`, включно з помилками та скасуванням.
  Завантаження до Telegram виконується з Buffer, з `voiceNote: true` та
  `DocumentAttributeAudio({ voice: true, duration })`, без файлового підпису.
- Помилка TTS чи FFmpeg дає текстовий fallback з тим самим текстом.
  При невизначеній помилці доставки Telegram повторної відправки немає, щоб
  не дублювати повідомлення. `/stop` скасовує аудіозапити й блокує пізнє надсилання.
- Подія `voice.text_fallback` містить `stage` (`tts` або `ffmpeg`) та `errorCode`.
  Для помилок Gemini також записуються модель і HTTP-статус, якщо він доступний.
  Коди: `VOICE_BAD_REQUEST` (400), `VOICE_AUTH` (401/403), `VOICE_MODEL` (404),
  `VOICE_RATE_LIMIT` (429), `VOICE_UNAVAILABLE` (408/5xx), `VOICE_NETWORK`
  (немає HTTP-відповіді). Для FFmpeg окремо розрізняються
  `VOICE_FFMPEG_NOT_FOUND`, `VOICE_FFMPEG_PERMISSION`, `VOICE_FFMPEG_TIMEOUT`
  та загальна помилка `VOICE_FFMPEG`. Тіла запитів, сирі відповіді провайдера,
  stderr FFmpeg і вміст аудіо до технічних помилок не додаються.
- Якщо розпізнавання не вдалося, агент не вигадує текст: реєструє помилку
  й показує повідомлення власнику в консолі.
- У `logs/agent-YYYY-MM-DD.jsonl` додаються події `voice.transcript` з полями
  `direction`, `transcript`, `bookingSessionId`. Вихідна транскрипція — текст,
  переданий TTS, а не повторне розпізнавання згенерованого аудіо. Застосовується
  маскування секретів, контактних даних і відомих приватних значень. Довільні
  невідомі імена в транскрипціях можуть залишатися в журналі.

## Моделі та тарифи — перевірено 18 листопада 2026

Офіційна документація описує
[Gemini 3.1 Flash-Lite](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-lite)
для мультимодального вводу та
[Gemini 3.1 Flash TTS Preview](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-tts-preview)
для генерації аудіо. TTS — legacy preview; вибрано сумісний із наявним
`generateContent` потоком, без переходу проєкту на Interactions API.

За [тарифами Gemini Developer API](https://ai.google.dev/gemini-api/docs/pricing):

| Модель | Вхід, USD / 1 млн токенів | Вихід, USD / 1 млн токенів |
| --- | --- | --- |
| 3.1 Flash-Lite | 0.50 аудіо; 0.25 текст | 1.50 текст |
| 3.1 Flash TTS Preview | 1.00 текст | 20.00 аудіо |

Для цих моделей описаний Free Tier, але його наявність не гарантує доступ
конкретному ключу. [RPM/TPM/RPD](https://ai.google.dev/gemini-api/docs/rate-limits)
визначаються проєктом і тарифом, перевіряються в
[AI Studio](https://aistudio.google.com/rate-limit). Перевищення будь-якої квоти
може повернути 429. У модулі реалізовано 60-секундну паузу окремо для кожної
аудіомоделі, без циклічних повторів; TTS у цей час переходить на текст.
Код не змінює тариф або billing. Точні квоти цього проєкту через Models API
не доступні й не були підтверджені.

Перевірка `models.get` з поточним локальним ключем:

- `gemini-3.1-flash-lite` — доступна; `generateContent`, вхід 1,048,576 токенів,
  вихід 65,536 токенів.
- `gemini-3.1-flash-tts-preview` — HTTP 404. Також перевірені
  `gemini-2.5-flash-preview-tts`, `gemini-2.5-pro-preview-tts`,
  `gemini-3.8-flash-lite-tts`: усі повернули HTTP 404.

Причину 404 (відсутність моделі чи доступу в цьому проєкті) API однозначно
не встановлює. Окремий короткий запит `generateContent` до
`gemini-3.1-flash-tts-preview` також не вдався: HTTP 400. Аудіо не отримано;
якість вимови не підтверджено.
Потрібен ключ/проєкт із доступною сумісною TTS-моделлю; до цього працює
текстовий fallback. Наявний `.env` та адресат Telegram не змінювались.

## Перевірки

```sh
npm run typecheck
npm test
npm run check:voice
# Лише за потреби: короткий синтетичний TTS → FFmpeg → STT, витрачає квоту API:
npm run check:voice -- --smoke
```

`check:voice` потребує попередньої збірки (`npm run build`). Він не відкриває
Telegram і не використовує сесію. Автоматичні тести використовують підміни
Gemini/Telegram та справжній FFmpeg для перевірки конвертації й очищення.
